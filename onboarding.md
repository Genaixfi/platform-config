# Team Onboarding Playbook

## Goal

Help Genaixfi engineering teams adopt Copilot Enterprise quickly, consistently, and safely.

## Three-stage onboarding model

### Stage 1 — Enablement

- confirm GitHub org and repo access
- assign Copilot Enterprise seats to the team
- validate IDE access for VS Code, JetBrains, and GitHub.com
- confirm team repository permissions and default branch protections

### Stage 2 — Pilot execution

- choose a pilot team with a representative repo
- agree on a few high-value workflows
- run a small set of code review and repo-analysis tasks
- collect feedback on usefulness, quality, and security concerns

### Stage 3 — Scale

- expand to additional repos and teams
- create reusable prompts and repo-specific playbooks
- formalize review and governance checkpoints
- publish lessons learned back into the org platform guide

## Recommended workflows to onboard first

- PR review support
- authentication and login flow explanation
- stack-trace debugging
- repo-intent summarization
- test generation for critical paths

## Standard onboarding checklist

- [ ] GitHub org access confirmed
- [ ] Repository access confirmed
- [ ] Copilot enabled for user or team
- [ ] IDE client installed and authenticated
- [ ] Repo-specific coding standards reviewed
- [ ] Security review expectations explained
- [ ] Example prompts shared
- [ ] Review process mapped to GitHub PR flow

## Team enablement guidance

New team members should receive:

- repo overview and ownership map
- architecture primer
- security boundaries and secrets rules
- starter prompts for daily work
- review expectations and escalation path

## Success measures

Track adoption through:

- active seat usage
- PR review usage
- issue and debugging cycle time
- time-to-onboard for new engineers
- reduction in repetitive coding tasks
